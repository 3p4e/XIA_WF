## Assumptions (correct me now if wrong)

1. **The AI image is the dial background** (`image_0000`, 464×464), and everything else is
   sprite/pointer overlay — the S3 has no arbitrary layer blending, only stacked elements.
2. **AOD face**: I will derive a dimmed, minimal AOD variant from the main face (black
   background or heavily dimmed art + grayscale readouts) — standard for S3 AOD.
3. **AI art needs post-processing**: OpenAI Image output is arbitrary-size RGB and far more
   than 256 colors. I must crop to 464×464, apply the circular dial mask, and quantize to
   **≤256 colors** (firmware decoder limit) before it's packable. This is a hard constraint.
4. **Analog hands are pointer elements** (`widge_pointer`), a different element type than the
   existing `Mono` digital face; I'll source the canonical pointer `prop7`/geometry from the
   same device-verified upstream reference used for `Mono`.
5. **Open Design integration path**: Open Design is OpenDesign v0.22.1 (self-hosted,
   Basic-auth `open-design` / `OD_API_TOKEN`). Image gen is driven through its **agent
   runtime + `imagegen` skill** (OpenAI Image), not a plain REST `/api/image` (that route
   does not exist). Fallback: call OpenAI Image API directly with the key already present in
   `od-deploy/.env` while still using Open Design to orchestrate prompts.
6. **Personal use only** — no commercial redistribution (consistent with repo license).

## Code Style

Match the existing `project/mono/gen_assets.py`: pure Pillow, no numpy, self-contained,
relative paths resolved from the script location, explicit 464×464 canvas and center
(232,232), `widge_dignum`/`widge_imagelist`/`widge_pointer` elements with device-verified
`dataSrc` ids and `prop7Raw` templates. Keep the generator deterministic and re-runnable.

## Testing Strategy

- **Artifact tests (script-level):** assert every output PNG ≤256 colors; dimensions ≤464;
  background image exactly 464×464.
- **Build verification:** pack → patch → unpack round-trip succeeds; byte-level header check
  (magic `5A A5 34 12`, smooth byte `1`, AOD face-record flags).
- **Visual preview:** render `preview.png` + `preview_aod.png` and inspect for clipped glyphs,
  overlaps, and contrast over the AI art.
- **On-device (human):** install `deliverables/AiArt.bin` — the only true acceptance test.

---

## Boundaries

- **Always:** quantize ≤256 colors/image; keep texture <4 MB/face; never re-pack from an
  `unpack`-ed `wfDef`; reuse device-verified `prop7Raw`/pointer geometry; run the packer
  pin + unpack verification.
- **Ask first:** which single art concept to finalize (after previews); enabling a provider
  key that isn't already in `od-deploy/.env`; adding new Python dependencies.
- **Never:** commit secrets/API keys; commit AI raw art with licensing ambiguity; redistribute
  commercially; push `build/` or `.class` artifacts.
